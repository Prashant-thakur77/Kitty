# Glossary

Every term a reviewer meets in the code, the dashboard and the documents, with one or two precise sentences and a pointer to where it lives. Contract line references are to [`src/asc/KittyLedger.sol`](../src/asc/KittyLedger.sol) unless another file is named. The system-level picture is in [`ARCHITECTURE.md`](ARCHITECTURE.md); the formal definitions in [`specs/PROTOCOL.md`](specs/PROTOCOL.md#1-definitions).

| Term | Definition | Where |
|---|---|---|
| Circle | A rotating savings group of 2 to 10 members with one installment amount, a round length in source-chain blocks, a start height, a vault and a chain key; created by `createCircle` (listed members) or `createOpenCircle` (filled by invites). A circle is `Active` until its last round closes, then `Completed`. | `KittyLedger.Circle`, `_initCircle`; [`PROTOCOL.md` 3.1](specs/PROTOCOL.md#31-kittyledgercircle) |
| Round | One installment period, numbered from 0; a circle of `n` members has rounds `0..n-1`, each `Open`, then `Closed`, then `Paid`. Its deadline is `startHeight + (round + 1) * roundBlocks`. | `KittyLedger.Round`, `deadlineHeight`; [`PROTOCOL.md` 4.2](specs/PROTOCOL.md#42-round) |
| Installment | The exact token amount each member pays into the vault per round, `Circle.contribution`, in 6-decimal `TestUSD` units. A proven payment of any other amount is rejected with `WrongAmount`. | `_recordContribution`; [`web/src/pages/Create.tsx`](../web/src/pages/Create.tsx) |
| Pot | The sum of proven contributions of a round, `Round.pot`, which `closeRound` assigns to the round's recipient; on Sepolia the vault keeps the matching escrow per circle in `KittyVault.pot[circleId]`. | `_recordContribution`, `closeRound`; [`src/source/KittyVault.sol`](../src/source/KittyVault.sol) |
| Rotation, `Fixed` | The classic order: the recipient of round `r` is `members[r]`, skipping anyone who did not pay this round or has already received. The default for every circle. | `Rotation.Fixed`, `_pickRecipient`; [`TECH.md`](TECH.md#rotation) |
| Rotation, `ByScore` | The recipient is the member with the highest Kitty Score among those who paid this round and have not received yet (ties go to the earlier member); set by the organiser with `setRotation` before round 0 holds any proof. | `Rotation.ByScore`, `setRotation`, `_pickRecipient` |
| Eligible recipient | A member with a proven contribution in the round being closed who has not received a pot in this circle (`receivedPot` false). Under either rotation the pot goes only to an eligible recipient. | `_pickRecipient`; [`adr/0004`](adr/0004-consent-grace-and-fallback-recipient.md) |
| `FallbackRecipient` | In the final round, when nobody is eligible because every payer has already received, the pot goes to any member who paid this round so escrow is never stranded; the event names that choice. | `closeRound`, `event FallbackRecipient` |
| Carry-over | When a non-final round closes with no eligible recipient, its pot is added to the next round's pot and `PotCarriedOver` is emitted; the round records no recipient. | `closeRound`, `event PotCarriedOver` |
| Consent | The `accepted[circleId][member]` flag that makes a member liable for a miss; granted by organising the circle, redeeming an invite, calling `acceptMembership`, or paying into the circle once. A listed member who never consented is never marked missed. | `_accept`, `acceptMembership`, `closeRound`; [`adr/0004`](adr/0004-consent-grace-and-fallback-recipient.md) |
| Grace window | `GRACE_BLOCKS = 64` source-chain blocks after a round's deadline during which a payment mined on time can still be proven; a round with missing payments can close only once `deadline + 64` is attested. | `GRACE_BLOCKS`, `closeHeight`, `closeRound`; [`adr/0001`](adr/0001-attestation-as-the-only-clock.md) |
| Attestation | An attestor-network statement, recorded on Creditcoin, that a source-chain block at a given height has a given hash; the ChainInfo precompile exposes it as a `HeightHash` (`height`, `hash`, `isAttestation`, `exists`). A miss carries the attestation that proved its deadline. | [`src/interfaces/IChainInfo.sol`](../src/interfaces/IChainInfo.sol); `Round.attestedCloseHeight` |
| Attested frontier | The highest source-chain height attested on Creditcoin, read with `get_latest_attestation_height_and_hash(chainKey)`; the dashboard shows it next to the Sepolia head as `lag`, and the batch policy measures slack against it. | [`web/src/hooks.ts`](../web/src/hooks.ts) `useAttestation`; [`worker/src/agent/policy.ts`](../worker/src/agent/policy.ts) `Frontier` |
| Chain key | The Attestcoin identifier of a source chain on Creditcoin (Sepolia is 1, Ethereum mainnet is 3 on CC3 Testnet). Each circle stores its own, creation validates it with `get_chain_by_key`, and the vault allowlist is keyed by it. | `Circle.chainKey`, `trustedVault`; [`PROTOCOL.md` 1](specs/PROTOCOL.md#1-definitions) |
| Continuity proof | The part of a Proof Builder response (`lowerEndpointDigest`, `roots[]`) that links a block's Kitty-Merkle root to an attested endpoint; one continuity proof can be shared by up to ten transactions in a batch. | [`web/src/lib/prover.ts`](../web/src/lib/prover.ts) `ContinuityProof`; [`worker/src/proofs.ts`](../worker/src/proofs.ts) |
| Merkle proof | The per-transaction inclusion proof (`root`, `siblings[{hash, isLeft}]`) against its block's transaction root, verified by the block prover together with the encoded transaction bytes. | [`web/src/lib/verifier.ts`](../web/src/lib/verifier.ts); [`ATTESTCOIN_INTEGRATION.md`](ATTESTCOIN_INTEGRATION.md) |
| Query id | `keccak256(chainKey ‖ height ‖ txIndex)`, the identity of a proven transaction, derived exactly as `ASCBase` does; `processedQueries[queryId]` is the replay guard shared by every entry point. | `_computeQueryId`, `_prepareBatch`; [`PROTOCOL.md` 10](specs/PROTOCOL.md#10-query-id-derivation) |
| `txIndex` | The transaction's position in its block, computed by the block prover from the Merkle proof's sibling path (`calculateTxIndex`) rather than supplied by the caller. | `_computeQueryId`; [`worker/src/verifier.ts`](../worker/src/verifier.ts) `txIndexOf` |
| Preflight | Asking the block prover's `verify` view whether a proof holds, and simulating the ledger call, before paying to submit; a rejected proof costs nothing. Done by the steward and by the browser. | [`worker/src/verifier.ts`](../worker/src/verifier.ts) `preflight`; [`web/src/components/ProvePanel.tsx`](../web/src/components/ProvePanel.tsx) |
| Proof-back | Proving the vault's `PaidOut` transaction to the ledger with `confirmPayout` or `confirmPayouts`, which is the only way a round moves from `Closed` to `Paid`. | `_confirmPayout`; [`ARCHITECTURE.md`](ARCHITECTURE.md#sequence-payout-and-proof-back-single-and-batch) |
| Steward | The off-chain worker in [`worker/`](../worker/) that scans vault payments, fetches proofs, submits them, closes rounds and executes payouts. It holds the vault operator key but no role on the ledger; anyone can do everything it does on Creditcoin. | [`worker/src/worker.ts`](../worker/src/worker.ts); [`TECH.md`](TECH.md#the-steward-three-layers) |
| Decision log | The append-only record of every steward decision (`prove`, `wait`, `close`, `payout`, `confirm`, `skip`, `error`) with the chain state it saw and the transactions it produced; the only facts Layer 3 may cite. Written to `worker/steward.local.json`. | [`worker/src/agent/log.ts`](../worker/src/agent/log.ts); [`web/src/pages/Steward.tsx`](../web/src/pages/Steward.tsx) |
| Citation validator | The guard on the model's answer: every figure must be wrapped `[[like this]]` and must appear in the decision log; a sentence with an unverifiable citation or an uncited figure is stripped before display. | [`worker/src/agent/citations.ts`](../worker/src/agent/citations.ts) `check` |
| Kitty Score | `500 + 15 * onTime - 20 * late - 120 * missed`, clamped to 300 to 850, computed on demand from the member's proof-backed record; readable by any Creditcoin contract. | `creditScore`; [`web/src/components/ScoreRing.tsx`](../web/src/components/ScoreRing.tsx) |
| Tier | The letter returned with the score: A at 700 or more, B at 600, C at 500, D below; `KittyCreditLine` maps it to 100 %, 50 %, 20 % and 0 % of proven volume. | `creditScore`; [`src/asc/KittyCreditLine.sol`](../src/asc/KittyCreditLine.sol) |
| Credit line | `KittyCreditLine`, the demo lender on Creditcoin that underwrites from the Kitty Score alone (`underwrite(address)` returns score, tier, limit and a reason), lends `KittyUSD` and adds a flat 5 % fee (`FEE_BPS = 500`). | [`src/asc/KittyCreditLine.sol`](../src/asc/KittyCreditLine.sol); [`web/src/pages/Borrow.tsx`](../web/src/pages/Borrow.tsx) |
| Badge | `KittyBadge`, an ERC-721 with the ERC-5192 `locked` interface, one per address (the token id is the address), whose SVG `tokenURI` is rendered on chain from the live ledger record. | [`src/asc/KittyBadge.sol`](../src/asc/KittyBadge.sol); [`web/src/components/BadgeCard.tsx`](../web/src/components/BadgeCard.tsx) |
| Proof Builder | The hosted Attestcoin service (`prover.cc3-testnet.creditcoin.network`) that returns encoded transaction bytes, Merkle proofs and a continuity proof for one transaction (`proof-by-tx`) or up to ten (`proof-batch-by-tx`), plus the attested height. It serves CORS `*`, so the browser can call it. | [`web/src/lib/prover.ts`](../web/src/lib/prover.ts); [`worker/src/proofs.ts`](../worker/src/proofs.ts) |
| Block prover | The precompile at `0x0000000000000000000000000000000000000FD2` (`INativeQueryVerifier`): `verify` as a view, `verifyAndEmit` for the state-changing call in single and batch overloads, and `calculateTxIndex`. The ledger's `VERIFIER`. | [`ATTESTCOIN_INTEGRATION.md`](ATTESTCOIN_INTEGRATION.md); [`web/src/lib/verifier.ts`](../web/src/lib/verifier.ts) |
| ChainInfo | The precompile at `0x0000000000000000000000000000000000000fD3` that answers questions about attestations and source chains: `is_height_attested`, `get_latest_attestation_height_and_hash`, `find_lowest_attested_after`, `get_attestation_bounds`, `get_chain_by_key`, `get_supported_chains` and two more. The ledger's `CHAIN_INFO`. | [`src/interfaces/IChainInfo.sol`](../src/interfaces/IChainInfo.sol) |
| ASC | Attestcoin Smart Contract: a Creditcoin contract that acts on foreign-chain transactions verified by the block prover. `KittyLedger` is one; it re-implements `ASCBase`'s verify, dedupe, act pipeline rather than inheriting it. | `KittyLedger` header comment; [`ATTESTCOIN_INTEGRATION.md`](ATTESTCOIN_INTEGRATION.md) |
| USC | Universal Smart Contract, Creditcoin's name for the same ecosystem; `@gluwa/usc-sdk` is the TypeScript SDK the worker uses for the Proof Builder client, transaction encoding and gas estimation. | [`worker/src/proofs.ts`](../worker/src/proofs.ts); [`worker/src/chain.ts`](../worker/src/chain.ts) |
| Writability | The Attestcoin write-ability layer: a Creditcoin contract publishes a message through an outbox, attestors attest it, and a receiver executes it on the destination chain. Not used by this build; it would replace the vault operator for payouts and enable refunds. | [`TECH.md`](TECH.md#what-writability-changes); [`adr/0002`](adr/0002-money-and-rules-on-different-chains.md) |
| Local world | Two anvils (chain ids 11155111 on 8545 and 102031 on 8546) with every contract deployed and both precompiles mocked at their real addresses, started by `scripts/local-setup.sh` and populated by `scripts/local-world.sh`; the mocked frontier is moved by hand. | [`OPERATIONS.md`](OPERATIONS.md#local-world-scripts) |
| Lab | The attack lab: the `/lab` dashboard page plus the local lab API (`pnpm lab:api`, port 8790) that runs scenarios and streams their logs; on the hosted build the page shows the run recorded against the testnets. | [`worker/src/api.ts`](../worker/src/api.ts); [`web/src/pages/Lab.tsx`](../web/src/pages/Lab.tsx) |
| Scenario | One of the eight attack-lab cases in `SCENARIOS` (`replay`, `spoofEmitter`, `wrongChain`, `revertedTx`, `stealFromSteward`, `fireTheAgent`, `poisonReasoning`, `late`), each pushing a real transaction through proof, precompile and ledger and comparing the decoded outcome with an expected error or event. | [`worker/src/scenarios.ts`](../worker/src/scenarios.ts); [`THREAT_MODEL.md`](THREAT_MODEL.md) |
